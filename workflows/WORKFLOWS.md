## 5. 출력 품질 검증 프롬프트

LLM 답변 **이후** 아래 블록을 이어서 붙여 넣어 주세요.

```
역할: 비판적 검토자. 방금 생성된 분석·권고안을 검증해 주세요.

다음 내용을 포함해 주세요:
1. 논리 오류: 인과관계가 끊긴 부분, 순환 논증, 근거 없는 주장.
2. 구체성 부족: "개선", "강화", "최적화" 등 모호한 표현과 구체화 제안.
3. 누락 항목: 프롬프트에서 요청했으나 빠진 섹션.
4. 실행 가능성: 담당·기한·예산이 없는 권고 지적.
5. 반론 시뮬레이션: 회의적인 이사회/CFO가 제기할 질문 3개와 대응 초안.
6. 개선 우선순위: 가장 먼저 수정할 3가지.

형식: 제목, 표(문제·개선안), 불릿으로 구조화해 주세요.

[검증할 LLM 답변 전체를 붙여 넣어 주세요]
```

## 8. 메타 프롬프트 체인 (부록 Part 8)

도메인별 ID 규칙: **8-{도메인번호×3-2} PE**, **+1 Agent**, **+2 Fact Checker**

| 도메인 | PE | Agent | Fact Checker | 본 Part |
|--------|-----|-------|--------------|---------|
| 전략 | 8-1 | 8-2 | 8-3 | Part 1 |
| 마케팅 | 8-4 | 8-5 | 8-6 | Part 2 |
| 커머스 | 8-7 | 8-8 | 8-9 | Part 3 |
| 기획 | 8-10 | 8-11 | 8-12 | Part 4 |
| PR | 8-13 | 8-14 | 8-15 | Part 5 |
| 데이터 | 8-16 | 8-17 | 8-18 | Part 6 |
| 조직 | 8-19 | 8-20 | 8-21 | Part 7 |

### 권장 3단계 (품질·자동화)

```
1) 본 프롬프트 실행 (예: 1-7 SWOT)
2) 8-3 Fact Checker — LLM 답변 전문 붙여넣기
3) (선택) 8-1 PE — 자주 쓰는 프롬프트 개선본 저장
4) (선택) 8-2 Agent — 반복 분석 자동화 설계
```

### PR 배포 전 4단계

```
5-2 보도자료 → 8-15 Fact Checker → 5-9 규제 체크 → 5-3 피칭
```

### 데이터 리포트 4단계

```
6-1 GA4 분석 → 8-18 Fact Checker → 6-3 스토리텔링 → (선택) 8-17 Agent 설계
```
